01 / PROJECT

项目介绍

以检测批次和病害编号为主线，把采集、解析、定位、评估、处置和报告组织成一条可追溯的本地演示闭环。

项目目标

面向隧道衬砌检测业务，展示从检测任务配置、雷达数据管理、数值处理和病害复核，到三维数字孪生、结构健康评估、预警治理和报告导出的完整工作台。

  • 统一批次、里程、环号、坐标和病害编号。
  • 让列表、雷达证据、三维场景和评估结果相互联动。
  • 在检测任务页面用设备示意图说明现场采集、记录、复核和安全保障的组成。

当前平台形态

根入口是 index.html，采用纯 HTML、CSS 和原生 JavaScript，在本机浏览器运行；默认演示无需后端服务，也不需要构建前端项目；外部实时接入需要用户提供视频 / 雷达网关地址。

  • 启动器：启动平台.cmd / 启动平台.py
  • 共享状态：当前浏览器的 localStorage

数据与证据

平台内置示范隧道、检测批次、病害台账、雷达纹理、评估配置和仿真参数，用于展示业务流程。外部 CSV / JSON、HTTP / WebSocket 雷达帧和现场视频保留来源，未保存帧只预览，不会自动覆盖演示病害。

  • 演示数据与导入数据在页面和导出中分开标识。
  • 红色候选、模型名称和置信度不等于工程确诊。
02 / ARCHITECTURE

系统架构与运行边界

平台以一个根入口承载四个业务模块，底层由共享状态和计算核心串联；隧道影像三维复核属于 02 / 智能解析，用于识别候选的影像与三维证据复核，03 / 孪生评估与运维负责工程空间定位、健康评估和处置闭环。

业务数据与页面联动场景 / 资源复用仿真参数回流检测工况
03 / MODULES

四个业务模块详细介绍

四个模块不是四个独立网页，而是同一个本地工作台中的业务分区；页面之间通过批次、任务、病害、坐标和评估状态连接。

项目总览 · 业务导航

总览不是第五个业务模块，而是跨模块驾驶舱。它聚合检测进度、病害记录、结构健康指数和待处置预警，并提供完整演示流程入口。

#overview完整演示流程进入模块

统一主线

批次 → 任务 → 数据 → 病害 → 坐标 → 评估 → 处置 → 报告。仿真工况可以回写检测任务参数，但仿真预测不会直接篡改实际 SHI 台账。

01

检测采集

设备、现场视频、仿真任务和雷达数据
#tasks#radar

检测任务页提供可展开的设备区、左侧现场视频与右侧仿真的同屏工作区、左侧病害标注区，以及画面下方的任务列表、全宽作业参数和日志；可配置里程、速度、扫描间距、扫描角和障碍物。雷达页先接入外部文件 / 网关帧，保存后进入处理；下方可查看同源病害复核或原有示意 B-scan。

  • 展开“设备配置与项目示意”，查看三臂检测车、雷达、影像、定位、边缘终端和安全辅助六类配置。
  • 检测车作业场景先接入现场录像、网络视频 / MJPEG 或摄像头，再使用独立仿真场景；支持截图和下载视频接入记录。
  • 启动 / 继续 / 暂停 / 重置检测任务，进度与三维车辆同步。
  • 第一人称视角、车载 B-scan、HUD、自动停障和自由漫游均保留；雷达 HUD 位于左下角，紧凑显示，作业详情可展开，面板可收起。
  • 外部 CSV / JSON 与 HTTP / WebSocket 帧统一校验，显示采集和接收时间；手动保存形成处理快照，停止或离页会释放接入。
主要输入批次、视频文件 / 网络源 / 摄像头、里程、速度、扫描参数、CSV / JSON 矩阵、网关帧和标定
主要输出视频画面、截图和接入记录；仿真任务状态、轨迹、雷达目录、矩阵快照和数据来源

新增现场病害对应：冻结视频帧 / 固定雷达快照，选择病害类型和位置；按录像时间 / 雷达道号检查先后顺序。左侧视频标注与右侧仿真同屏核对，原仿真可切换现场标注，同源雷达复核共用矩阵与标记；折叠区域不重建媒体或场景，原有第一人称、启停、设备、背景和图层保留。

关联 → 保存外部帧后向智能解析提供固定矩阵；视频和实时预览不自动写入病害，为三维和仿真提供检测工况。
02

智能解析

预处理、模型契约和人工复核
#processing#defects

负责数值预处理、病害候选复核和隧道影像三维复核。当前减背景、线性时间增益等矩阵处理可执行；真实识别模型以适配器契约展示接入边界，内置病害明确标识为演示台账。

  • 对比原始矩阵与处理后矩阵，显示参数、版本、耗时和来源。
  • 按类型、风险、复核状态、置信度和里程筛选病害。
  • 通过“定位”进入三维场景，通过“证据”查看雷达和关联信息。
  • 病害复核页面底部嵌入隧道影像三维复核，保留多场景原始页面、候选证据和返回导航。
主要输入雷达矩阵、标定元数据、处理参数、病害台账
主要输出处理矩阵、候选列表、复核状态、证据入口
关联 → 用病害编号连接雷达证据、三维坐标、SHI 和预警。
03

孪生评估与运维

定位、SHI、预警、治理和报告
#twin#health#alerts#reports

这是业务闭环的核心模块。三维场景提供洞内、横断面、拱顶、仰拱、全景、第一人称和自由漫游等视角；健康评估使用 AHP / 熵权组合计算 SHI；预警、治理和报告保存处置结果。

  • 病害列表、三维点选、环向展开图、横断面和历史批次联动。
  • 星空 / 城市背景、透明度、剖切、自动旋转、图层、启动暂停和全屏均保留。
  • 通过“返回影像三维复核”回到第二模块证据区，完成复核后再进行工程空间定位和健康评估。
主要输入病害编号、位置、尺寸、复核状态、批次和评估配置
主要输出三维证据、SHI、风险、预警、HTML / CSV / JSON / PDF

新增证据孪生定位：选择相同任务与来源，三维、展开图、横断面共用 E- 编号和精确坐标，可返回原视频时间 / 雷达道号。尺寸是定位符号，不填造风险或历史；演示评估通过原有台账模式继续使用。

关联 → 接收解析结果，向预警和报告提供评估；治理动作保留轨迹。
04

仿真推演

在明确假设下比较参数变化
#simulationsamplevehiclestructureplans

提供可复现雷达示意样本、检测车作业验证、简化闭合圆环结构响应和运维方案比较四个页签，用于理解参数敏感性和业务决策关系。

  • 作业验证参数可应用回检测任务，观察速度、间距和障碍物影响。
  • 结构响应支持导入外部有限元 JSON 作为参考展示，不写入 SHI。
  • 运维方案按预算、工期和预期降险进行演示排序。
主要输入样本参数、车辆工况、结构参数、预算权重
主要输出示意信号、覆盖率、响应量、方案比较
关联 → 作业验证可回写检测场景参数；方案预测与实际 SHI 分开保存。
04 / RELATIONS

模块关联与数据流

每个页面都围绕同一个浏览器状态工作。切换页面不是复制数据，而是通过同一批次和同一病害实体重新渲染；识别候选先在 02 / 智能解析中完成影像复核，再交给 03 / 孪生评估与运维完成工程定位和健康评估。

01检测批次B202609 / 历史批次
02检测任务里程、速度、启停
03雷达数据CSV / B-scan / 元数据
04病害候选筛选、证据、复核
05三维定位坐标、环位、视角
06健康评估SHI / 风险 / 变化
07处置输出预警、治理、报告

共享实体

检测批次决定数据隔离；病害编号连接列表、雷达证据、三维位置和报告；坐标定义让里程、环号、环向角、埋深和 Y/Z 坐标保持一致。

状态联动

任务启动、暂停和进度会同步车辆与车载面板；筛选条件会同步三维可见对象和 HUD 提示；修改 α、AHP 矩阵或分级规则后，SHI、风险、预警和报告重新计算。

仿真回流

仿真作业验证可以把速度、扫描间距和障碍物应用到检测任务；结构响应和运维方案只作为独立预测结果展示，不直接伪装成实测或修改历史评估。

影像复核边界

隧道影像三维复核属于智能解析的证据环节，通过 iframe 保留原始 HTML、viewer.js、scene_data.js、影像和录像；复核结论仍需人工确认，三维数字孪生只接收已关联的病害编号和位置。

实时预览与固定快照

现场视频保留真实帧、时间和像素点，已保存雷达快照保留道 / 采样点。人工标注后形成统一 E- 病害记录，驱动作业仿真与第三模块的精确定位。后续网络帧不覆盖旧快照，原始视频 / 矩阵需单独下载；现场候选不自动进入 SHI。

资源边界

本次发布包含现场对应、视频与仿真并排布局及紧凑车载雷达面板；在线内容以 GitHub Pages 成功部署的版本为准。主工作台通过本地 vendor/three.min.js 和内部场景组件运行；多场景页面由共享主题 CSS 统一，不覆盖原始场景文件。

同编号、同类型、同顺序、同位置

现场视频时间 / 像素点与雷达快照道 / 采样点 → 人工 E- 标注 → 01 作业对应场景 → 03 三维、展开图和横断面 → 返回原证据。相对定位用于保持对应关系，真实测量须有标定；修改统一记录同步更新所有视图，来源与批次 / 任务隔离。

05 / USER MANUAL

平台使用流程 · 分步说明书

19 步说明书：先接入与标注，再核对仿真 / 孪生，最后保存。第一次使用建议按顺序完成。每一步都给出入口、操作动作和完成标志；熟悉后可直接从左侧导航跳到需要的模块。

先跑通原有演示流程，也可使用本地三个公开验证视频添加人工候选。导入矩阵不自动识别，现场对应标注与原有评分台账独立。

  1. 启动本地工作台建立正确的本地 HTTP 环境和浏览器状态

    保留整个“三维孪生平台”目录，双击 启动平台.cmd。如果没有自动打开浏览器，访问 http://127.0.0.1:8765/index.html；端口被占用时运行 python 启动平台.py --port 8766。

    1. 确认浏览器支持 WebGL。
    2. 首次使用时不要清理站点数据，平台状态保存在当前浏览器。
    3. 结束工作时回到终端按 Ctrl+C 停止本地服务。
    完成标志：看到“项目总览”页面，顶栏显示示范隧道和当前检测批次。
    入口启动平台.cmd → index.html#overview
  2. 先看项目总览，确认批次和演示边界了解当前状态，再决定从哪一个业务模块开始

    在总览查看任务进度、病害数量、结构健康指数和待处置预警。点击顶部“检测批次”可以切换最新批次与历史批次；点击“完整演示流程”会按业务顺序引导进入各页。

    • 内置病害、示意雷达、历史派生和仿真参数都带有演示标识。
    • 本地状态只属于当前浏览器、端口和文件模式。
    完成标志：明确当前批次，例如 B202609，并知道数据是否为演示或导入来源。
    入口#overview → 完整演示流程
  3. 创建或调整检测任务把项目范围、车辆参数和作业工况设定好

    进入“检测采集 → 检测任务与设备”。先按需展开顶部“设备配置与项目示意”，点击设备卡片了解配置。中间工作区左侧为现场视频、右侧为对应仿真，左侧视频下方可展开病害标注；任务列表、全宽作业参数与日志位于工作区下面。点击“新建检测任务”填写名称与范围，再通过工作区顶部“作业参数”按钮到达表单，设置车速、间距、扫描角和障碍物后点击“应用参数”。

    1. 设备图是配置示意，真实设备接入还需要驱动、采集协议、标定和现场安全验证。
    2. 里程必须落在 K3+128—K3+176 范围内，起点小于终点。
    3. 障碍物位置以项目起点为 0 m，车辆会按平面包围盒提前停障。
    4. 需要复现默认结果时，先使用内置任务参数，不要立即修改。
    完成标志：任务状态为“待开始”，场景中的检测车和任务参数与表单一致。
    入口#tasks → 检测采集 → 检测任务与设备
  4. 接入现场视频，区分实时画面与录像先看真实视频，再标注类型、顺序与相对位置

    在同屏工作区左侧找到“检测车作业场景 · 现场视频”。本地录像通过文件选择导入；网络监测填入 HTTP(S) 视频直链或 MJPEG 地址；摄像头 / 采集卡通过浏览器授权直接接入。展开“来源、时间与接入说明”查看来源与播放位置；桌面直接与右侧仿真对照，宽度小于 1000 px 时恢复单列。

    1. 本地录像始终标为回放。网络源用途由源端确认，不能把本机呈现时间当成现场采集时间。
    2. 摄像头仅请求视频，不启用麦克风。RTSP / RTMP 需要源端视频网关转换，HLS 需浏览器原生支持。
    3. 接收到画面后再截图为 PNG，并下载独立的接入记录 JSON。跨域源不允许取帧时会提示截图限制。
    4. 切换任务 / 批次会断开原来源；离开页面会释放摄像头、断开网络源并暂停录像。实时源返回后需要手动重新连接。
    完成标志：看到实际画面、明确来源类型和任务关联。单纯接入不会生成病害；冻结标注后可联动仿真与孪生，显式录像联动可驱动车辆，不改写演示台账或 SHI。
    入口#tasks → 现场视频 → 本地录像 / 网络监测源 / 摄像头 → 截图 / 接入记录
  5. 标注视频病害并核对仿真位置没有真值也能保持原帧、先后顺序和相对位置一致
    1. 点击顶部“病害标注与对应”展开左侧对应区，确认任务与批次；录像暂停到候选病害处，点击顶部“冻结视频并标注”（或区内“冻结当前视频帧”）。
    2. 点击冻结画面中的病害，人工选择类型。相对规则按时间 / 视频时长映射任务起止里程；横向映射默认 60°—120°，按镜头朝向调整；表面深度为 0。真实坐标可改用人工工程位置并写依据。
    3. 点击“保存对应病害”，按视频顺序继续取帧。系统拒绝时间与里程先后倒置；同一病害多帧可关联已有编号。
    4. 点击“定位并对齐车”，再勾选录像联动并播放，查看车辆按相同进度经过各标记。直播没有时长，需人工给位置。
    完成标志：每条记录有真实帧、E- 编号、类型、时间和坐标；场景只显示所选来源，类型与位置一致。
    入口#tasks → 冻结视频并标注 → 左侧点击位置 → 保存 → 右侧对应仿真
  6. 运行检测车并体验原有交互验证启动、暂停、第一人称和自由漫游

    在同屏工作区右侧找到“检测车作业场景 · 仿真演示”，点击“开始 / 继续”。桌面滚动左侧标注时右侧场景保持可见；展开工具后可在右侧面板内部滚动。需要观察车辆内部时点击“第一人称视角”。左下角车载雷达默认显示剖面和里程；点击“作业详情”展开全部指标，标题右侧“− / +”收起或恢复面板，方便观察车辆和机械臂；按 P 可以启停作业，按 F 退出第一人称，按 G 切换自由漫游，W/A/S/D 移动、Q/E 升降、Shift 加速。

    • 独立仿真时，暂停只冻结作业时钟，第一人称相机仍可操作。录像联动时车辆由录像进度控制；取消联动可恢复原启停。
    • 场景工具可以开关车载 HUD、雷达射线、轨迹、病害标签、星空和城市背景。
    • 按 Esc 可以直接退出第一人称或释放场景操作。
    完成标志：任务进度、车辆位置、车载 HUD 和任务状态同步变化；暂停后车辆坐标冻结。
    入口#tasks → 第一人称视角

  7. 导入外部雷达矩阵并对照仿真外部数据在上，独立示意信号在下

    1. CSV 为无表头纯数值矩阵；JSON 帧须含 matrix，格式见 examples/radar_stream_sample.json。
    2. 检查来源声明、任务 / 批次、测线、采集和导入时间；格式样例明确为非实测。缺少标定显示道号 / 采样点，不补造物理尺度。
    3. 外部图与下方“仿真演示”的控件独立；在“当前数据”或目录选择外部快照作为处理输入。非法值、尺寸、关联或标定冲突会被拒绝。
    完成标志：外部数据目录中有独立快照，来源与标定可核对，原始数值可导出 CSV / JSON。

    在雷达页选择“设备 / 网关数据源”，按源端协议选择 HTTP(S) JSON 帧轮询或 WebSocket 文本 JSON 帧，填写设备 / 网关地址后连接。平台没有内置网关或专有设备驱动。

    1. HTTP 间隔 1～30 秒，跨域端点需允许读取；WebSocket 每条消息是完整矩阵，最多预览每秒 5 帧，超出不展示 / 归档。
    2. 收到合法数据后检查帧编号、源端采集时间、本机接收时间和重复统计；重复帧不会伪装成新采集。错误帧和任务 / 批次冲突会拒绝。
    3. 点击“保存本帧到数据目录”，当前数据选中该固定快照，再进入智能处理。后续网络帧不覆盖已保存或已处理矩阵。
    4. 下载当前矩阵 CSV 与接入 JSON，结束后停止。离开雷达页停止连接；返回需手动重连，任务 / 批次变化清除旧预览。
    完成标志：目录中出现正确关联的网关帧快照，采集时间与接收时间分开展示，实时预览与仿真信号没有混用。
    入口#radar → 网关地址 → 连接 → 保存本帧 → 智能处理
  9. 标注雷达异常并核对同道同点原始矩阵、对应复核与孪生共用固定证据
    1. 选择已导入 / 保存且绑定当前任务的快照，点击“冻结当前雷达快照”。
    2. 在剖面点击异常或填 0 起始的道号 / 采样点，选择类型。缺标定按道顺序和采样序号形成相对位置，明确非实测埋深。
    3. 有标定时输入测线起点、正负方向、环位、表面零点，确认道间距、采样间隔、介电常数，点击“应用雷达标定”；参数不足会拒绝。
    4. 保存病害，下方使用同一矩阵显示同一道 / 点的标记。需原示意信号时切回“原有演示台账”。
    完成标志：上下剖面标记落在同一道 / 采样点；类型与第三模块一致，不把重新生成信号当作对应结果。
    入口#radar → 固定快照 → 冻结 → 道 / 点 → 保存对应病害

    • 模型接口页面用于说明真实算法所需输入、输出和失败信息。
    • 当前未接入真实 RCAN、RTM、TunGPR/T-GPRMask 推理服务时，平台会明确提示未接入。
    完成标志：处理状态完成，输入 / 输出矩阵可对照，模型未接入不会被误认为已完成识别。
    入口#processing → 运行数值预处理

    进入“智能解析 → 病害清单与复核”。按病害类型、风险等级、复核状态、最低置信度和里程筛选；点击“证据”看雷达，点击“定位”进入三维场景。

    1. 在详情中登记通过、待复核或驳回等状态。
    2. 当前内置病害是演示台账；导入矩阵不会自动变成识别结果。
    3. 选择 D-001 可以完整体验后续三维、健康、预警和报告联动。
    完成标志：选中一个病害编号，例如 D-001，并能在列表、证据和三维场景中找到同一个对象。
    入口#defects → 证据 / 定位

    留在“智能解析 → 病害清单与复核”页面，向下滚动到“隧道影像三维复核”。先选择多场景总览，再进入 DVP 手持、铁路短片、铁路长片或 TUM VI 鱼眼场景，核对候选与同帧影像证据。

    • 选择“规则化表面 / 原始重建”，再按需开启候选位置、拍摄轨迹、纹理和分割掩码。
    • 使用三维拖动、右键平移、滚轮缩放、帧滑块和前后按钮检查邻帧；红色标记是待人工复核候选，不是确诊结果。
    • 场景页顶部提供“返回场景总览”和“返回智能解析”，主页面面板也提供“返回病害清单”。
    完成标志：候选编号、原始影像、三维表面和复核状态围绕同一个候选实体对应起来。

    • 场景工具可以控制透明度、纵向剖切、管片、钢筋、注浆、地层、车辆、射线、轨迹、风险热力和标签。
    • 顶部“返回上一页”会回到刚才的病害复核页面；“返回影像三维复核”可以直接回到第二模块的证据区。

    查看现场标注时，在三维数字孪生的对应区选择相同任务、“当前任务现场标注”和正确源。三维、展开图、横断面共用精确坐标，不吸附环中心；“原视频位置”“原雷达位置”可回到原帧 / 快照，原视频文件和雷达矩阵须可用。

    完成标志：病害点、环向展开图、横断面和当前批次围绕同一编号同步。

  14. 计算结构健康指数并做敏感性检查确认评分配置、风险等级和历史变化

    进入“孪生评估与运维 → 结构健康评估”。查看全隧道 SHI、区段评估、指标严重度、AHP 权重和熵权；调整 α 查看组合权重敏感性，必要时修改判断矩阵和分级阈值。

    • α = 1 表示纯 AHP，α = 0 表示纯熵权，结果会联动 SHI、风险、预警和报告。
    • 严重局部病害可触发最高风险，不会被全隧道平均值完全稀释。
    • 历史批次使用同一当前评估配置，便于比较批次差异。
    完成标志：知道当前 SHI、风险等级、评估版本和参数来源，并确认是否需要保留默认配置。

    • 预警保留触发依据、关联病害和操作日志。

07 / LIMITS

使用边界与常见误解

这些说明用于避免把可操作演示误认为已经完成了真实工程接入。

演示数据 ≠ 现场结论

内置病害、示意雷达、历史批次、几何停障、圆环结构响应和方案降险比例均是演示或比较假设，需要专业复核和现场数据标定。

外部接入不自动识别

视频用于观察取证；外部雷达文件和网关帧用于矩阵查看，手动保存后建立预处理输入。实时性和标定需源端核验，专有雷达协议待适配；不自动生成病害，真实模型仍待接入。

本地状态 ≠ 数据库备份

业务状态在浏览器 localStorage 中保存，浏览器清理、换端口或换设备会产生独立状态；重要结果必须导出，原始矩阵需单独保存。

仿真预测 ≠ 工程鉴定

仿真用于参数敏感性、作业设计和方案比较；外部有限元只做结构化展示，不代表求解器正确，也不替代承载力、运营安全或病害鉴定。

现场对应与验证边界

3 个公开混凝土视频、9 条人工候选观测已验证类型、顺序和相对位置对应；素材不是本项目隧道实测，无工程里程真值。现场标注共用精确坐标，三维大小只是定位符号；未自动识别，不填造尺寸、风险或 SHI。现场对应代码与配套文档纳入本次 GitHub 发布，公开测试视频与验收输出保留在本地。

完整步骤见《平台使用说明》，来源和 170 项 / 组验收见《验证记录》。原视频、来源清单和最终结果保留，临时抽帧与调试中间文件清理。
