# 隧雷智检 · 隧道智能检测与数字孪生运维平台

本地运行的中文工作台，依据《计划.docx》的四项内容组织为“检测采集、智能解析、孪生评估与运维、仿真推演”，并以项目总览串联业务。平台以视频档案隔离现场成果，以病害编号和批次组织独立演示台账，可演示从检测任务到报告导出的完整流程。

本版本包含实际可执行的 CSV 解析、数值预处理、AHP/熵权计算、参数化三维联动和本地处置记录。内置病害、示意雷达信号、健康评分配置与仿真预测均明确标记为演示；影像裂缝检测已有独立算法流程；通过本地启动器导入现场视频后，会自动启动本机 Python 推理，输出代表帧、裂缝掩码、叠加图和候选 JSON，并进入第二模块的多相机建模与裂缝候选复核；GPR 设备控制尚未接入；雷达页只导入 CSV / JSON 或接收 HTTP / WebSocket 网关帧，雷达矩阵不会送入影像模型；仿真雷达样本在第四模块单独生成；视频支路自动输出裂缝候选，检测完成后可手动启动 CPU 三维重建与局部定位；未命中区域保留未定位，人工复核与工程标定后再进入正式台账和工程定位。原有演示病害与健康评分保持独立。

## 当前视频数据管理与启动状态（2026.10.08.6）

**每次重启本地服务，或者另开一个平台窗口，都从“未选择视频”的初始工作台开始。** 不自动恢复上次视频，不自动加载历史候选、模型、SHI、预警、报告或仿真结果；雷达输入未选择，数值处理为空，车辆进度归零并停止，作业 / 评估 / 视图参数使用初始值。项目、批次和任务定义保留，四个业务模块和原有交互功能仍在。

**初始化的是当前界面，已有数据不删除。** 同一个视频的各阶段成果仍保存在以下目录；新导入只建立另一个视频档案并接管当前视图，原视频的上传副本、检测、复核、三维与下游文件全部保留。新版已取消旧版的替换自动删除和后台清理重试。

```text
<videoId>/
├─ source.json                 # 原件路径、SHA-256、浏览器证据来源编号
├─ manifest.json               # 视频身份、任务归属、阶段状态与文件索引
├─ job.json                    # 检测任务状态
├─ input/                      # 本机上传的原始视频副本
├─ frames/                     # 本视频代表帧与帧元数据
├─ detect/                     # detections.json、掩码与红色叠加图
├─ review.json                 # 检测生成的帧证据和完整候选清单（兼容原路径）
├─ acquisition/annotations.json# 本视频人工疑似位置标注
├─ review/decisions.json        # 本视频候选复核决定与备注
├─ reconstruction.json         # 当前手动重建任务状态
├─ reconstruction/<runId>/     # 模型、相机、定位 JSON、质量记录和复核页面
├─ twin/state.json             # 引用本视频模型与定位的孪生状态
├─ health/assessment.json      # 本视频健康评估；缺少工程依据时 SHI / 风险为空
├─ operations/state.json       # 本视频预警与治理状态
├─ simulation/state.json       # 本视频仿真输入 / 结果状态
└─ reports/                    # 同源 report.json 与深色 report.html
```

`source.json` 记录视频编号、完整 SHA-256、批次 / 任务和来源；候选版本与模型归属也会核验。页面只有在手动选中视频后才读取其成果，缺少阶段保持待完成；`health/assessment.json` 缺少物理标定和实测依据时不生成工程评分。

页面上方“数据来源”默认是 **未选择视频**。需要继续旧视频时，先选择对应批次 / 任务，点击“刷新档案目录”，再手动选中视频；各业务模块一起加载该视频的数据。“独立演示台账 / 建模案例”也需手动选择，原有案例、第一人称、启停、背景图层和仿真功能均保留。

重启 / 新窗口初始化前，上一次浏览器工作记录会完整归档到 `runtime/workbench_sessions/W-<校验值>.json`，包括雷达矩阵、复核记录、参数及选择状态。需要这些旧工作参数时，从“历史工作状态”选择档案，再点“加载工作状态”；只有此明确操作才恢复旧状态。同一窗口在同一次服务运行中普通刷新或 Ctrl+F5 可续接当前选择与任务状态；关闭后台服务会中断尚未完成的计算，需要重新导入检测或重试建模。

启动器增加 `/api/workbench/session` 与归档接口，新功能需重新启动 `启动平台.cmd` 并 Ctrl+F5，页脚确认 **2026.10.08.6**。只使用静态预览时，工作状态副本保留在浏览器本地历史区，不代表已保存到 Python 服务磁盘；浏览器禁止存储或归档失败时不会覆盖原记录。

本次修改仅保存在本地，不推送 GitHub。详细操作见 [平台使用说明](平台使用说明.md)。

## 启动

推荐在本目录双击 **启动平台.cmd**。启动器使用 Python 3 标准库，仅监听本机回环地址，并打开：

```text
http://127.0.0.1:8765/index.html
```

也可在本目录运行：

```powershell
python 启动平台.py
```

端口被占用时运行 `python 启动平台.py --port 8766`；无需自动打开浏览器时添加 `--no-browser`。终端按 `Ctrl+C` 停止服务。

前端无需构建、无需 npm 安装，默认演示不需要付费服务、API 密钥或联网接口；接入网络视频或雷达帧时需有可访问的设备 / 网关地址。也可双击 `index.html` 使用文件模式，但浏览器对 `file://` 的本地存储与页面通信存在差异，推荐以上 HTTP 方式。请保留整个目录，不能只复制一个 HTML 文件；三维场景需要支持 WebGL 的浏览器。

## 现场疑似位置对应复核

**位置复核与录像联动一起用：**“现场与仿真 · 同屏对照”上方增加常驻的“疑似位置复核”栏，列出本视频各点的编号、录像时间和对应里程，并提示本帧／下一处疑似点。点击编号会暂停到原帧，同时定位仿真点并对齐车辆；开启“到点暂停复核”后，播放录像会按出现顺序停回每个标记的原帧，点击视频播放继续下一处。顺序栏在证据面板折叠时仍可见；视频像素点仅出现在保存的帧附近，避免把固定像素点假装成跨帧追踪。

**标记与示例：**自己的录像可点击常驻栏“标记疑似位置”，在冻结原帧点选并点击“保存位置并同步仿真”；支持方向键选点、“返回视频”或 Esc 取消。新点只记位置、类型待识别。已下载的三段隧道检测录像会出现“载入本视频示例位置”：按完整文件 SHA-256 匹配本地人工复核索引，从当前录像实际取帧，各载入 3 个待复核位置，不是算法检测结果或确诊病害。重复载入不重复记录，换源取消未完成的取帧，已有标注保留。点击人工修订过工程坐标的点时会关闭连续相对进度联动，以保留修订后的车辆定位；不再按旧时间比例覆盖人工坐标。公路车载雷达示例使用 `highway-tunnel-gpr-h264.mp4`，只选第一处隧道的 10 / 14 / 18 秒。

**无标注也可联动：**在常驻栏勾选“录像联动车辆”，或在原“疑似位置与对应”面板勾选“录像播放联动仿真车”，两处开关共用状态。勾选即对齐当前录像位置，车辆随后随播放、暂停和进度拖动同步；不要求先标点或导入 JSON。取消勾选后录像与原有仿真启停恢复各自操作。摄像头 / 实时流没有固定录像进度，仍在原证据面板取帧并填写人工位置。

第一阶段“检测任务与设备”负责拍摄、观察和记录疑似位置，不承担病害类型判断。新视频记录的 `type=null`、`classificationStatus="pending"`；保存时间、原始帧中的点击坐标 `(u,v)`、任务与来源、定位依据和 `E-` 编号。采集仿真统一使用青绿定位点，显示同一编号与顺序，不绘制假定的裂缝、空洞等病害形状。类型判断留给第二阶段的识别与复核；导入录像会启动本地 Python 裂缝候选推理，结果进入第二模块候选复核区，人工确认后才进入正式病害清单。

1. **视频 → 三维作业对照**：在左侧导入录像，暂停在疑似位置，点击常驻栏“标记疑似位置”，在冻结画面点选后点击“保存位置并同步仿真”；原“冻结视频并标记”与“保存疑似位置”流程也可继续使用，无需选择类型。默认 `里程 = 任务起点 + 时间/时长 × 任务长度`，横向像素映射到可设置的环向扇区，表面深度为 0。记录时刻附近（±0.12 秒）原视频显示编号点，按 `object-fit:contain` 的实际画幅位置绘制，包含黑边换算；此点不追踪目标。勾选录像联动或点击“定位并对齐车”，核对右侧同一编号、位置与出现顺序，定位后百分比、距离与任务状态同步刷新。
2. **雷达 → 对应复核**：冻结已保存的快照，选择道号 / 采样点。可只标位置、类型留空，也可保留已有分类。下方对应剖面使用同一矩阵与标记；缺标定仅作相对定位，有测线标定时填写起点、方向、环位、表面零点，并核实道间距、采样间隔和介电常数后换算。
3. **仿真 → 孪生 → 原证据**：第三模块选择相同任务、现场标注模式和数据源。未识别点继续使用中性定位点，三维、展开图、横断面使用同一坐标；原视频位置 / 原雷达位置按钮返回原来源。原有已分类记录的信息继续保留；采集场景只展示其位置。
4. **修改和备份**：统一修改位置，拒绝同源时间或道号与里程先后倒置；手工改坐标后原相对映射失效。同一物理疑似点在多帧出现应关联已有编号，不重复算作多处。对应 JSON 升级为 `schemaVersion:2`，允许类型为空，并兼容原 `schemaVersion:1` 备份。导入校验坐标基准、任务、来源与编号，原视频和完整雷达矩阵需另存。

接入新的录像会自动切换到当前源的现场对应模式，尚未记录疑似点时右侧为空；不会拿原有演示病害替代。可随时切回“原有演示台账”。第一人称、启动 / 暂停、HUD、图层、背景、全屏、任务配置和原 16 处演示病害继续使用，现场采集记录不改变演示 SHI、预警或报告。

相对映射用于保持观测时间、画面位置和示意里程的对应；竖向像素只作证据保留，不自动换算工程环位。固定机位、转动镜头或非匀速录像需要实测里程与姿态标定才能恢复物理位置，不能把时间进度当作实际车速或实测里程。

当前验证素材已全部换为 **3 段真实隧道检测作业视频**：轨道隧道扫描设备近景、同一作业的人员跟拍，以及高速公路隧道车载探地雷达检测。两段轨道隧道视频属于同一作业，不作为三个独立工程样本。原非隧道视频、播放副本和旧标注已撤回清理。每段记录 3 条待复核位置，共 9 条，不指定类型；接缝或表面痕迹不等于确诊病害，也不作识别准确率或实测定位精度结论。车载原片为 HEVC，另生成不裁剪视频画幅和时序的 H.264 副本，原片及双方校验值保留。三段原片、H.264 播放副本及来源清单随仓库保存在 [`assets/videos/`](assets/videos/README.md)；验收结果和对应 JSON 仍在被忽略的本地 `tests/output/`，详见 [验证记录](验证记录.md)。

直接试用：下载 [`assets/videos/`](assets/videos/README.md) 中的播放文件，在“检测任务与设备 → 现场视频”打开，例如 `assets/videos/highway-tunnel-gpr-h264.mp4`，点击“载入本视频示例位置”，无需预先导入 JSON；在 **10、14、18 秒**查看第一处隧道内的三条未分类待复核位置，勾选录像联动或使用定位按钮对照。原片后段有道路及软件结果画面，本例不在这些画面上选点。不要重复导入同编号；雷达回溯另需原浏览器中同编号的固定快照。

完整步骤见 [平台使用说明](平台使用说明.md)，模块关系与 19 步说明书见 [平台架构与使用流程](平台架构与使用流程.html)。

## 现场视频监测、自动推理与三维作业对照

进入“01 检测采集 → 检测任务与设备”，在左侧接入现场视频，与右侧三维作业对照：

1. **本地录像回放**：选择浏览器可解码的 MP4 / WebM 等文件，直接播放、暂停和拖动进度；文件只在本机读取，明确显示为录像回放。
2. **网络监测源**：填写设备或视频网关提供的 HTTP(S) 视频直链，选择视频 / MJPEG 格式及源端用途，再点击“连接视频源”。网络源的直播真实性和延迟仍需由源端核实。
3. **摄像头 / 采集卡**：通过本地启动器进入平台，选择默认或指定设备并允许摄像头权限；仅采集视频，不请求麦克风。
4. **自动 Python 推理**：本地录像选择后，平台把文件发送给启动器提供的回环 API；服务按均匀时间点抽取代表帧，调用 `algorithm/defect_detect.py` 的 crack-seg U-Net，并在页面中轮询显示进度。
5. **截图与追溯**：接收到画面后可截图为 PNG，并下载独立的视频接入记录 JSON，包含任务、批次、来源、截图时间和录像位置；推理结果另存于本地 `runtime/video_inference/<任务号>/`。

原生 HLS 仅在浏览器自身支持时播放；RTSP / RTMP 地址需要设备或视频网关先转成浏览器可播放的 HTTP(S) 地址。网络源可能允许观看而禁止跨域截图，界面会提示限制。刷新浏览器不会自动恢复文件选择或视频连接；任务 / 批次改变会断开原来源，切换到其他业务页会暂停录像、断开网络源并释放摄像头，返回后可手动重连。

视频播放、自动推理和三维作业对照仍是三个边界清晰的环节：播放不等于识别，Python 只输出裂缝候选，不生成雷达数据、不控制真实检测车，也不自动修改演示病害台账。自动推理需要通过 `启动平台.py` 访问本机 API；直接双击 `index.html` 时仍只能播放视频。主工作台项目 JSON 包含业务台账及现场对应记录，推理原始视频、掩码和 review.json 保存在本地运行目录，HTML 演示报告仍以评估台账为范围。


## 02 智能解析：自动检测、手动建模与候选复核

导入录像后，平台按“本地上传 → 代表帧抽取 → crack-seg U-Net 推理 → 掩码 / 叠加图 / review.json → 多相机建模与裂缝候选复核”的顺序执行。默认按视频进度均匀抽样，页面可选择 8、16 或 24 帧；任务在后台运行，完成后在 `#defects` 页面显示采样帧数、候选数量、阈值、设备和候选缩略图。候选红色区域只表示模型输出，必须结合原始帧、邻帧和三维表面人工复核，确认后再进入病害清单和三维定位。

本机推理服务由 `启动平台.py` 提供，仅监听 `127.0.0.1`，不会把视频上传到互联网。服务优先复用启动器 Python；当前环境需要 `torch`、`opencv-python`、`numpy`、`scipy`、`Pillow`，模型权重和第三方 crack-seg 源码位于本地 `algorithm/video_reconstruction/`，不随静态网页自动下载。

为保证普通 Windows 电脑在推理时仍可操作，默认采样为 8 帧，Torch CPU 线程上限为 2；页面仍可手动选择 16 或 24 帧。检测与三维重建共用一个本地资源槽位；重建运行时不能同时导入另一个视频进行推理。重复点击建模返回同一任务，失败后可重试。

视频推理状态约每 850 ms 读取一次。相同状态或只有后台日志追加时，不发送重复前端事件、不写本地存储、不更新页脚；进度变化直接修改固定字段，完成时显示候选结果。智能处理和候选复核页采用稳定显示：同时关闭整页、深层空状态与状态灯循环动画，侧栏 / 顶栏使用同色实色背景并停用背景模糊，保留输入、焦点、图表和内嵌场景。其他模块与 iframe 内的三维交互保持原样。终端中的 `GET /api/video-inference/status?... 200` 仍是正常查询日志。本次增加了后端重建接口：当前检测结束后关闭旧启动窗口，重新运行 `启动平台.cmd` 或 `python 启动平台.py`，再按 `Ctrl+F5`，页脚应显示“界面版本 2026.10.08.6”；仍有异常时可在影像推理卡片点击“导出显示诊断”，得到当前页面地址、资源版本、接口查询、整页重绘调用和 DOM 变化的本地 JSON，不自动上传视频或诊断。

### 检测完成后手动三维重建与定位

1. 在“01 检测采集 → 检测任务与设备”导入录像，等“02 智能解析 → 智能处理工作流”的 Python 检测显示已完成。
2. 在影像卡片下方的“三维重建与定位”选择补抽建模帧数（24 / 48 / 72，默认 24），点击 **运行三维重建与定位**。候选复核页也提供同一入口。未完成检测时按钮禁用，不会自动建模。
3. 服务复用本次 `detections.json` 与原检测帧，额外抽取相邻帧，运行 CPU SIFT、时间邻帧匹配、SfM 相机恢复；增量重建不足时尝试全局 SfM。原检测候选不会再次识别或被覆盖。
4. 查看注册帧、稀疏地标、有坐标候选观测数量以及圆柱规则化表面三角面数量。完成后点击 **打开本次视频三维复核**，进入“多相机建模与裂缝候选复核”的 **本次视频重建** 场景；默认查看圆柱规则化观察面，也可切换“原始重建”；原有五个案例入口保留。
5. 在模型中旋转、缩放，切换“当前帧视角”，用帧滑块查看同帧影像 / 掩码，选择红色候选对照位置；“定位 JSON”“几何质量”“本次建模日志”可分别下载。新增场景提供返回候选复核和智能处理工作流的按钮。

补抽帧仅用于几何；总建模帧还包含原检测帧并去除重复，不等于再次检测全部帧。新视频复核默认显示**圆柱规则化隧道观察表面**：它依据本次视频恢复的相机轨迹与观测点拟合圆柱断面，使新视频与历史建模案例保持一致；“原始重建”仍可切换查看真实稀疏观测三角面；圆柱规则化面使用历史案例一致的中性灰材质，现场图像纹理只保留给原始观测面。候选是否获得三维坐标仍以原始观测面的同帧射线命中为依据，圆柱面只把已有命中点关联到规则化显示面，不为未命中候选补造坐标。两种表面都不是完整稠密网格，坐标为单目相对尺度，不能直接换算工程里程或裂缝尺寸；未注册帧、缺少支撑或未命中的候选保持空坐标。定位结果仍属于第二模块，不自动写入第三模块正式台账或 SHI。

任务状态持久保存在 `runtime/video_inference/<检测任务ID>/job.json` 和 `reconstruction.json`；建模输出位于 `reconstruction/<本次运行ID>/`，含 `sfm/scene.json`、`sfm/quality.json`、`localized_defects.json` 和 `web/index.html`。浏览器刷新可续接正在运行的建模；后端重启会把中断任务标记为可重试，完成成果保留。该目录仍被 Git 忽略，原视频和运行结果不自动发布。

本机当前使用 Python 3.12 / PyCOLMAP 4.1.1 CPU，无须 CUDA。重建 Python 需要 `pycolmap`、`scipy`、`numpy`、`opencv-python`、`Pillow`；可通过 `SLZJ_RECONSTRUCTION_PYTHON` 指定环境。原有稠密 CUDA 流程保持独立。建模需连续视角、有纹理和足够重叠；短测试建议先使用 `assets/videos/multiscene/dvp-handheld.webm`，弱纹理、纯旋转、混剪等输入可能明确失败。

### 使用建模案例的原视频试跑

DVP 手持、铁路短片、铁路长片的原始视频已整理到本地 `assets/videos/multiscene/`，原片哈希与 `algorithm/experiments/captures.json` 一致。建议先在“01 检测采集 → 检测任务与设备 → 现场视频”选 8 帧，导入 `rail-tunnel-short.mp4`，再到 02 查看本次候选。完整步骤和校验见 [素材说明](assets/videos/multiscene/README.md) 与 [来源清单](assets/videos/multiscene/sources.json)。

当前快速检测使用原始 `unet_v3.pth` 权重与默认 0.70 阈值；下方已有三维案例使用 CTCD 来源分组调优权重与 0.85 阈值，且选帧不同，因此同一原视频不保证相同候选数量。原片导入自动执行裂缝检测；后续三维重建需在检测完成后点击按钮，不自动触发；TUM VI 是走廊图像序列，本次未下载大型数据包。媒体保留本地，下载复现使用 `python tests/download_multiscene_videos.py`，不会自动发布。

## 雷达外部数据与对应复核

进入“01 检测采集 → 雷达数据管理”，页面只保留“雷达采集 · 外部数据”及现场证据对应区，负责文件 / 网关接入、快照目录、B-scan、单道波形和智能处理入口。原来的程序仿真雷达样本不再混在采集页，统一移到“04 仿真推演 → 01 雷达样本”；真实外部数据与仿真样本因此不会混用。

1. **外部文件**：选择数值 CSV，并按需导入 / 粘贴 JSON 标定；也可直接导入包含 `matrix` 和 `metadata` 的 JSON 帧文件。点击“解析并导入”后显示来源声明、任务 / 批次、测线、源端采集时间和本机导入时间。样例明确标为非实测，外部文件的真实性不由平台自动确认。
2. **设备 / 网关数据源**：选择 HTTP(S) JSON 帧轮询或 WebSocket 文本 JSON 帧，填写源端地址并连接。HTTP 间隔为 1～30 秒；WebSocket 最多显示每秒 5 帧，超出帧不展示或归档。网关需提供完整矩阵快照，HTTP 跨域读取需源端允许；当前没有内置雷达网关或专有设备驱动。
3. **保存后再处理**：接收帧只预览，点击“保存本帧到数据目录”后形成独立快照，并选为“当前数据”。再点击“进入智能处理”运行实际预处理，后续接收帧不改写已保存快照。
4. **原始数据保存**：可下载当前矩阵 CSV 和含完整矩阵、标定、来源、时间与最近接入事件的 JSON。主工作台项目 JSON / HTML 报告仍不附带原始矩阵；重要数据需另行保存。

重复帧不会刷新采集 / 接收时间；错误帧、批次 / 任务冲突、超限数据和二进制专有流会明确拒绝。离开雷达页停止网络接入，返回需要手动重连；切换任务或批次会释放连接并清除旧预览，避免数据串用。未保存的接入帧刷新后丢失，已保存目录沿用本地浏览器存储。

坐标轴仅使用已提供的标定；缺少道间距或时间标定时显示道号 / 采样点，不补造物理埋深。图像色标和单道波形做显示归一化，原始数值保持不变。JSON 接入格式见 [雷达帧样例](examples/radar_stream_sample.json) 和 [数据接入说明](真实算法与数据接入说明.md)。

## 默认项目与数据边界

- 示范隧道长 **48 m**，里程 **K3+128—K3+176**，40 环、环号 980—1019，环宽 1.2 m，内半径 2.7 m，衬砌厚度 0.35 m。
- 最新批次为 `B202609`，历史批次为 `B202607`；16 条演示病害沿用原平台。历史直径与长度按当前值的 0.8 倍、面积按 0.64 倍派生，并非历史实测。
- 列表、三维与证据通过病害编号联动；复核按批次独立保存。CSV 导入的数据保持独立来源，**不会自动生成或覆盖病害台账**。
- 项目 JSON 导出按当前批次筛选任务、预警、日志、雷达目录与治理任务。全批次评估与当前筛选诊断分分别输出；没有批次归属的外部分析明确标记为项目全局参考。
- 当前窗口状态保存在浏览器 `localStorage` / `sessionStorage`；文件录像成果在本机视频目录中保存，重启前旧工作状态另行归档到本机 `runtime/workbench_sessions/`，可手动加载。所有接口仅访问本机，不向互联网上传；静态预览的历史区仅存在该浏览器内。项目结果 JSON 仍不是原始矩阵备份，完整工作归档包含原雷达矩阵。

所有非总览页面的标题右侧都提供“← 返回上一页”和“返回项目总览”。页面内从病害清单进入三维定位时，返回按钮会回到刚才的页面；多场景复核页还提供“返回场景总览”和“返回智能解析”，减少在子页面中迷路。

## 设计来源与对应关系

本次先阅读工作区《计划.docx》和《隧道智能检测与数字孪生平台_开发提示词.txt》，再分析 3 分 01.52 秒的模板演示视频。计划书实际为四项编号内容，因此设置四个一级业务模块，避免把所有功能堆在一个三维页面。

模板视频约 48～60 秒的原图/雷达与结果并列布局，被用于雷达管理和智能处理页；约 72～84 秒的三维、指标与环号查询关系，被用于孪生、病害清单和健康评估；约 96 秒的报告入口，被纳入可打印 HTML 报告中心。视频中的大语言模型知识问答未列入本次四部分计划，不在本版本中声称已实现。

新界面沿用深蓝工程底色，以绿色作为操作与选中状态，以红/橙/黄/绿表达风险；图表、清单与三维共用编号、里程、批次和评估版本。原有三维几何、检测车交互和背景资源融入新版工作台，各模块通过统一任务与病害数据联动。

## 录像三维重建与网格优化（手动桥接与原独立流程）

新增独立模块 [algorithm/README.md](algorithm/README.md)，包含真实隧道录像抽帧、COLMAP 相机与稠密表面重建、裂缝候选分割、三维射线定位、圆柱规则化观察面与原始／规则化表面对比页面模板。当前工作台视频按钮已将 CPU SfM 结果默认导出为本次视频拟合的圆柱观察面，同时保留原始观测面；已记录 DVP 公开视频的实际运行与验证结果。

该模块的代码和小型验证记录已入库；视频、模型权重、虚拟环境和大型重建产物由脚本在本地准备。现有 `启动平台.py` 会直接调用 `algorithm/defect_detect.py`，把本地录像的代表帧、掩码、叠加图和 `review.json` 写入候选复核区；完整 COLMAP 重建与正式病害台账回填仍需单独运行和人工确认。环境、数据来源和完整命令见 [算法与重建说明](algorithm/README.md)；`algorithm/video_reconstruction/` 仅保留本地辅助环境、模型缓存和第三方实验文件，不是主工作台的启动依赖。

## 当前采用的影像检测算法

当前影像病害检测采用 `algorithm/defect_detect.py` 中的 **crack-seg U-Net 裂缝分割流程**。算法目录还包含抽帧、三维重建、病害射线定位、网格优化和复核页面导出；其中录像导入后的裂缝候选由本地启动器桥接执行并回传到 02 模块，本次视频的 CPU SfM、原始观测面射线定位、圆柱规则化观察面与复核导出已由手动按钮桥接；已有 CUDA 稠密建模与大型实验脚本继续保留为独立流程。规则化观察面使用中性灰材质，是显示与同场景对照先验；现场纹理只用于原始观测面，候选定位仍以原始观测命中为准。

| 环节 | 当前代码与输出 |
|---|---|
| 输入准备 | `reconstruct.py` / `keyframes.py` 提取与选择原始影像帧 |
| 裂缝候选检测 | `defect_detect.py` 加载本地权重，输出掩码、候选观测和 `detections.json` |
| 模型实验 | `segmentation_experiment.py` 提供裂缝分割训练、验证与保留集评估流程 |
| 三维定位与复核 | `localize_defects.py` 与 `export_web.py` 生成定位输出和离线复核页面 |

在“智能解析 → 智能处理工作流”的“影像检测 · Python 自动推理”卡片查看运行状态，点击“进入多相机候选复核”查看当前任务结果；环境、权重准备及完整运行命令见 [algorithm/README.md](algorithm/README.md)。源码和权重须按其来源说明在本地准备。

本次移除旧候选识别下拉框、相应工作流步骤与默认注册项。当前影像算法输出的是**裂缝候选**，不代表已支持界面中全部人工标注类别，也不代表确诊。视频导入后的任务结果会自动写入本地候选复核区，但不会直接修改正式病害台账、演示 SHI 或三维确诊状态；候选需结合原始帧、掩码、相邻帧和三维证据人工确认。RCAN / RTM 继续作为雷达处理的待接入接口，不能替代上述影像检测。

## 开发验证复现

日常运行不需要安装 npm 包。开发人员可运行 `npm test` 执行核心、适配器与现场对应核心测试；如需复现浏览器验收，先安装开发依赖 `npm install`，运行本地启动器，再运行 `npm run test:browser`、`npm run test:retained`、`npm run test:entry`、`npm run test:video`、`npm run test:radar`、`npm run test:evidence` 、`npm run test:layout` 、`npm run test:positions` 、`npm run test:follow` 和 `npm run test:review`。位置复核专项覆盖三段隧道录像的人工示例、原帧与仿真编号坐标、逐点暂停、快速采集、刷新恢复与换源取消；录像联动专项覆盖无标注录像的实际连续播放、暂停、进度拖动、换源、取消勾选及无时长实时源；对应与同屏布局验收使用三段真实隧道检测视频（来源与选点统一保存在 `tests/tunnel-video-cases.json`）；完整下载仓库即包含 `assets/videos/` 中的原片和播放副本，可用 `python tests/download_public_videos.py` 校验，测试优先读取该目录，无需另装 FFmpeg。素材缺失且需要从原来源重新准备时运行 `python tests/download_public_videos.py --ffmpeg "你的 ffmpeg.exe 路径"`，将车载雷达 HEVC 原片另转为 H.264 副本并保留原片。FFmpeg 仅用于准备测试素材，日常运行不需要这些测试媒体。测试默认使用 Windows 已安装的 Microsoft Edge；其他位置可通过环境变量 `BROWSER_EXECUTABLE` 指定。新增 `npm run test:inference-ui` 专项使用独立临时静态服务和固定 API 响应，在真实浏览器中验证状态轮询、输入与场景保留、完成与失败展示，不启动 Python 模型。 `npm run test:inference-pixels` 再比较连续截图的实际像素：相同状态全页应无差异，进度变化只允许推理卡片内改变；需要 Pillow，解释器可由 `PIXEL_TEST_PYTHON` 指定。 已准备本地环境与铁路短片后，可选择运行 `npm run test:inference-live`，使用独立端口完整验证真实视频上传、8 帧 CPU 推理、显示稳定性和候选复核；解释器通过 `VIDEO_INFERENCE_PYTHON` 指定。真实界面测试将原片另制成 320×180 临时副本，保留 395 帧及原时序后跑 8 帧推理，避免把高分辨率计算压力混入闪屏验收；不用于评价原片的识别准确率或完整性能。测试只删除自己新建的任务与副本目录，保留用户结果，验收摘要与截图保存在已忽略的 `tests/output/`。浏览器验收的截图、下载文件和机器可读结果按需写入 `tests/output/` 临时目录；该目录已被 Git 忽略，报告清理后重新运行测试会生成；随仓库素材缺失时，可恢复 `assets/videos/` 或重新下载并准备兼容播放副本。
