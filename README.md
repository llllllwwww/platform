# 隧雷智检 · 隧道智能检测与数字孪生运维平台

本地运行的中文工作台，依据《计划.docx》的四项内容组织为“检测采集、智能解析、孪生评估与运维、仿真推演”，并以项目总览串联业务。平台共用病害编号、检测批次、坐标、评估和处置记录，可演示从检测任务到报告导出的完整流程。

本版本包含实际可执行的 CSV 解析、数值预处理、AHP/熵权计算、参数化三维联动和本地处置记录。内置病害、示意雷达信号、健康评分配置与仿真预测均明确标记为演示；影像裂缝检测已有独立算法流程，结果尚未自动接入工作台；GPR 设备控制尚未接入；现场视频可接入外部画面，雷达页可导入 CSV / JSON 或接收 HTTP / WebSocket 网关帧；接入画面或矩阵本身不会产生识别结论；视频采集只记录疑似位置、出现时间和先后顺序，仿真与第三模块孪生共用这些记录；新视频点不判断类型，类型识别由第二阶段独立算法承担，并可显式开启录像进度联动车辆。原有演示病害与健康评分保持独立。

## 在线访问

**https://llllllwwww.github.io/platform/**

平台通过 GitHub Pages 提供在线入口，浏览器直接打开即可使用，无需安装任何环境。建议使用支持 WebGL 的现代浏览器（Chrome / Edge / Firefox / Safari）。本次发布包含现场视频与外部雷达接入、视频与仿真并排布局、紧凑车载雷达面板，以及最新的常驻疑似位置复核栏、原帧快速标记、同源人工示例与到点暂停复核。`main` 分支更新后由 GitHub Pages 构建，在线内容以成功部署的版本为准；仓库提交与网页部署状态分别核查。

本次更新将算法说明统一为当前裂缝分割流程，移除旧候选识别入口；视频到算法结果的自动回填仍未开发。检测任务与设备只记录疑似位置，新点类型留空，仿真与孪生使用同一编号和坐标；录像联动支持无标注视频，勾选即对齐当前位置。三段真实隧道录像可显式载入人工预选的复核位置；三段原片和车载雷达 H.264 播放副本现随仓库提供在 `assets/videos/`，来源及 SHA-256 见该目录的说明；用户录像、算法数据与验收输出仍留在本地。README、使用说明、验证记录、架构手册与四阶段说明已同步更新。

## 启动

推荐在本目录双击 **启动平台.cmd**。启动器使用 Python 3 标准库，仅监听本机回环地址，并打开：

```text
http://127.0.0.1:8765/index.html
```

也可在本目录运行：

```powershell
python 启动平台.py
```

端口被占用时运行 `python 启动平台.py --port 8766`；无需自动打开浏览器时添加 `--no-browser`。终端按 `Ctrl+C` 停止服务。

前端无需构建、无需 npm 安装，默认演示不需要付费服务、API 密钥或联网接口；接入网络视频或雷达帧时需有可访问的设备 / 网关地址。也可双击 `index.html` 使用文件模式，但浏览器对 `file://` 的本地存储与页面通信存在差异，推荐以上 HTTP 方式。请保留整个目录，不能只复制一个 HTML 文件；三维场景需要支持 WebGL 的浏览器。

“检测任务与设备”页面展开“设备配置与项目示意”后，用零依赖内嵌 SVG 展示六类项目配置：三臂智能检测车、车载探地雷达阵列、影像与照明单元、定位与姿态采集、边缘采集与数据终端、安全与辅助保障。点击卡片可查看它与平台页面、数据链路的对应关系；这些图是配置和交互说明，不代表真实硬件已经接入。
检测页改为同屏工作区：顶部为可展开的设备配置区；**左侧现场视频，右侧对应仿真**（采集只标疑似位置，不选类型），两个画面等高对齐；左侧视频下面展开“疑似位置与对应”。桌面滚动标注时右侧仿真保持可见，任务列表、全宽作业参数和日志放在工作区下方。设备、来源说明和标注区域的折叠只改变显示，不重建视频或场景。

工作区顶部提供“冻结视频并标记”“疑似位置与对应”“作业参数”三个快捷入口。宽度 ≥1000 px 使用双栏，较窄屏幕改为单列；参数表单随宽度采用四、二或一列。视频默认独立播放；在标注区勾选“录像播放联动仿真车（按相对进度）”后，才按该录像的相对进度驱动车辆。原有设备卡片、第一人称、启停、HUD、背景、图层、全屏和任务设置均保留。

第一人称车载雷达 HUD 改为左下角紧凑卡片，让出中央车辆和机械臂视野。默认显示雷达剖面、里程与提示；点击“作业详情”展开环号、速度、机械臂和断面信息，标题右侧“− / +”可收起或恢复整个面板。折叠只调整显示，不重建画布或改变作业状态。

隧道影像三维复核已整合到根目录 `index.html` 的 `#defects` 智能解析页面中，作为病害候选识别后的证据复核区。它包含 `algorithm/web/multiscene` 下的多场景总览、DVP 手持、铁路短片、铁路长片和 TUM VI 鱼眼五个原始 HTML 页面；切换场景时仍使用各自原来的 `viewer.js`、`scene_data.js` 和资源文件。

使用方法：启动平台后进入“智能解析 → 病害清单与复核”，向下滚动到“隧道影像三维复核”。先用“多场景总览”查看重建统计，再切换 DVP 手持、铁路短片、铁路长片或 TUM VI 鱼眼。场景页中的“规则化表面 / 原始重建”、候选位置、帧滑块、分割掩码和录像回放均保持原有交互；页面背景由 `algorithm/web/multiscene/platform-theme.css` 统一到主工作台的深蓝黑与青绿色主题。红色标记仍表示待人工复核的候选，不代表已确认病害。完成后点击页面标题右侧“返回上一页”或场景页顶部“返回智能解析”，再进入第三模块做工程定位。

## 现场疑似位置对应复核

**位置复核与录像联动一起用：**“现场与仿真 · 同屏对照”上方增加常驻的“疑似位置复核”栏，列出本视频各点的编号、录像时间和对应里程，并提示本帧／下一处疑似点。点击编号会暂停到原帧，同时定位仿真点并对齐车辆；开启“到点暂停复核”后，播放录像会按出现顺序停回每个标记的原帧，点击视频播放继续下一处。顺序栏在证据面板折叠时仍可见；视频像素点仅出现在保存的帧附近，避免把固定像素点假装成跨帧追踪。

**标记与示例：**自己的录像可点击常驻栏“标记疑似位置”，在冻结原帧点选并点击“保存位置并同步仿真”；支持方向键选点、“返回视频”或 Esc 取消。新点只记位置、类型待识别。已下载的三段隧道检测录像会出现“载入本视频示例位置”：按完整文件 SHA-256 匹配本地人工复核索引，从当前录像实际取帧，各载入 3 个待复核位置，不是算法检测结果或确诊病害。重复载入不重复记录，换源取消未完成的取帧，已有标注保留。点击人工修订过工程坐标的点时会关闭连续相对进度联动，以保留修订后的车辆定位；不再按旧时间比例覆盖人工坐标。公路车载雷达示例使用 `highway-tunnel-gpr-h264.mp4`，只选第一处隧道的 10 / 14 / 18 秒。

**无标注也可联动：**在常驻栏勾选“录像联动车辆”，或在原“疑似位置与对应”面板勾选“录像播放联动仿真车”，两处开关共用状态。勾选即对齐当前录像位置，车辆随后随播放、暂停和进度拖动同步；不要求先标点或导入 JSON。取消勾选后录像与原有仿真启停恢复各自操作。摄像头 / 实时流没有固定录像进度，仍在原证据面板取帧并填写人工位置。

第一阶段“检测任务与设备”负责拍摄、观察和记录疑似位置，不承担病害类型判断。新视频记录的 `type=null`、`classificationStatus="pending"`；保存时间、原始帧中的点击坐标 `(u,v)`、任务与来源、定位依据和 `E-` 编号。采集仿真统一使用青绿定位点，显示同一编号与顺序，不绘制假定的裂缝、空洞等病害形状。类型判断留给第二阶段的识别与复核，当前裂缝算法独立运行，尚未自动回填工作台。

1. **视频 → 仿真**：在左侧导入录像，暂停在疑似位置，点击常驻栏“标记疑似位置”，在冻结画面点选后点击“保存位置并同步仿真”；原“冻结视频并标记”与“保存疑似位置”流程也可继续使用，无需选择类型。默认 `里程 = 任务起点 + 时间/时长 × 任务长度`，横向像素映射到可设置的环向扇区，表面深度为 0。记录时刻附近（±0.12 秒）原视频显示编号点，按 `object-fit:contain` 的实际画幅位置绘制，包含黑边换算；此点不追踪目标。勾选录像联动或点击“定位并对齐车”，核对右侧同一编号、位置与出现顺序，定位后百分比、距离与任务状态同步刷新。
2. **雷达 → 对应复核**：冻结已保存的快照，选择道号 / 采样点。可只标位置、类型留空，也可保留已有分类。下方对应剖面使用同一矩阵与标记；缺标定仅作相对定位，有测线标定时填写起点、方向、环位、表面零点，并核实道间距、采样间隔和介电常数后换算。
3. **仿真 → 孪生 → 原证据**：第三模块选择相同任务、现场标注模式和数据源。未识别点继续使用中性定位点，三维、展开图、横断面使用同一坐标；原视频位置 / 原雷达位置按钮返回原来源。原有已分类记录的信息继续保留；采集场景只展示其位置。
4. **修改和备份**：统一修改位置，拒绝同源时间或道号与里程先后倒置；手工改坐标后原相对映射失效。同一物理疑似点在多帧出现应关联已有编号，不重复算作多处。对应 JSON 升级为 `schemaVersion:2`，允许类型为空，并兼容原 `schemaVersion:1` 备份。导入校验坐标基准、任务、来源与编号，原视频和完整雷达矩阵需另存。

接入新的录像会自动切换到当前源的现场对应模式，尚未记录疑似点时右侧为空；不会拿原有演示病害替代。可随时切回“原有演示台账”。第一人称、启动 / 暂停、HUD、图层、背景、全屏、任务配置和原 16 处演示病害继续使用，现场采集记录不改变演示 SHI、预警或报告。

相对映射用于保持观测时间、画面位置和示意里程的对应；竖向像素只作证据保留，不自动换算工程环位。固定机位、转动镜头或非匀速录像需要实测里程与姿态标定才能恢复物理位置，不能把时间进度当作实际车速或实测里程。

当前验证素材已全部换为 **3 段真实隧道检测作业视频**：轨道隧道扫描设备近景、同一作业的人员跟拍，以及高速公路隧道车载探地雷达检测。两段轨道隧道视频属于同一作业，不作为三个独立工程样本。原非隧道视频、播放副本和旧标注已撤回清理。每段记录 3 条待复核位置，共 9 条，不指定类型；接缝或表面痕迹不等于确诊病害，也不作识别准确率或实测定位精度结论。车载原片为 HEVC，另生成不裁剪视频画幅和时序的 H.264 副本，原片及双方校验值保留。三段原片、H.264 播放副本及来源清单随仓库保存在 [`assets/videos/`](assets/videos/README.md)；验收结果和对应 JSON 仍在被忽略的本地 `tests/output/`，详见 [验证记录](验证记录.md)。

直接试用：下载 [`assets/videos/`](assets/videos/README.md) 中的播放文件，在“检测任务与设备 → 现场视频”打开，例如 `assets/videos/highway-tunnel-gpr-h264.mp4`，点击“载入本视频示例位置”，无需预先导入 JSON；在 **10、14、18 秒**查看第一处隧道内的三条未分类待复核位置，勾选录像联动或使用定位按钮对照。原片后段有道路及软件结果画面，本例不在这些画面上选点。不要重复导入同编号；雷达回溯另需原浏览器中同编号的固定快照。

## 现场视频监测与仿真作业

进入“01 检测采集 → 检测任务与设备”，在左侧接入现场视频，与右侧仿真对照：

1. **本地录像回放**：选择浏览器可解码的 MP4 / WebM 等文件，直接播放、暂停和拖动进度；文件只在本机读取，明确显示为录像回放。
2. **网络监测源**：填写设备或视频网关提供的 HTTP(S) 视频直链，选择视频 / MJPEG 格式及源端用途，再点击“连接视频源”。网络源的直播真实性和延迟仍需由源端核实。
3. **摄像头 / 采集卡**：通过本地启动器进入平台，选择默认或指定设备并允许摄像头权限；仅采集视频，不请求麦克风。
4. **截图与追溯**：接收到画面后可截图为 PNG，并下载独立的视频接入记录 JSON，包含任务、批次、来源、截图时间和录像位置。

原生 HLS 仅在浏览器自身支持时播放；RTSP / RTMP 地址需要设备或视频网关先转成浏览器可播放的 HTTP(S) 地址。网络源可能允许观看而禁止跨域截图，界面会提示限制。刷新浏览器不会自动恢复文件选择或视频连接；任务 / 批次改变会断开原来源，切换到其他业务页会暂停录像、断开网络源并释放摄像头，返回后可手动重连。

视频区为独立的观察与取证入口，不会自动识别病害、生成雷达数据或控制真实检测车。主工作台项目 JSON 包含业务台账及现场对应记录，HTML 演示报告仍以原评估台账为范围；原视频与单独截图需另存，对应 JSON 会保留冻结帧。没有新增前端依赖或视频上传服务。

## 雷达外部数据与对应复核 / 原有仿真

进入“01 检测采集 → 雷达数据管理”，上方是“雷达采集 · 外部数据”，下方可在“雷达信号 · 仿真演示”和“雷达信号 · 同源病害对应复核”之间切换。原有 B-scan、单道切换、色标增益、横向缩放、示意异常区域、样例下载和智能处理入口均保留；两区使用独立的显示控件。

1. **外部文件**：选择数值 CSV，并按需导入 / 粘贴 JSON 标定；也可直接导入包含 `matrix` 和 `metadata` 的 JSON 帧文件。点击“解析并导入”后显示来源声明、任务 / 批次、测线、源端采集时间和本机导入时间。样例明确标为非实测，外部文件的真实性不由平台自动确认。
2. **设备 / 网关数据源**：选择 HTTP(S) JSON 帧轮询或 WebSocket 文本 JSON 帧，填写源端地址并连接。HTTP 间隔为 1～30 秒；WebSocket 最多显示每秒 5 帧，超出帧不展示或归档。网关需提供完整矩阵快照，HTTP 跨域读取需源端允许；当前没有内置雷达网关或专有设备驱动。
3. **保存后再处理**：接收帧只预览，点击“保存本帧到数据目录”后形成独立快照，并选为“当前数据”。再点击“进入智能处理”运行实际预处理，后续接收帧不改写已保存快照。
4. **原始数据保存**：可下载当前矩阵 CSV 和含完整矩阵、标定、来源、时间与最近接入事件的 JSON。主工作台项目 JSON / HTML 报告仍不附带原始矩阵；重要数据需另行保存。

重复帧不会刷新采集 / 接收时间；错误帧、批次 / 任务冲突、超限数据和二进制专有流会明确拒绝。离开雷达页停止网络接入，返回需要手动重连；切换任务或批次会释放连接并清除旧预览，避免数据串用。未保存的接入帧刷新后丢失，已保存目录沿用本地浏览器存储。

坐标轴仅使用已提供的标定；缺少道间距或时间标定时显示道号 / 采样点，不补造物理埋深。图像色标和单道波形做显示归一化，原始数值保持不变。JSON 接入格式见 [雷达帧样例](examples/radar_stream_sample.json) 和 [数据接入说明](真实算法与数据接入说明.md)。

## 默认项目与数据边界

- 示范隧道长 **48 m**，里程 **K3+128—K3+176**，40 环、环号 980—1019，环宽 1.2 m，内半径 2.7 m，衬砌厚度 0.35 m。
- 最新批次为 `B202609`，历史批次为 `B202607`；16 条演示病害沿用原平台。历史直径与长度按当前值的 0.8 倍、面积按 0.64 倍派生，并非历史实测。
- 列表、三维与证据通过病害编号联动；复核按批次独立保存。CSV 导入的数据保持独立来源，**不会自动生成或覆盖病害台账**。
- 项目 JSON 导出按当前批次筛选任务、预警、日志、雷达目录与治理任务。全批次评估与当前筛选诊断分分别输出；没有批次归属的外部分析明确标记为项目全局参考。
- 所有业务状态保存在当前浏览器的 `localStorage`，不上传服务器。不同浏览器、端口及文件模式拥有独立存储。浏览器清理数据后记录可能丢失，应及时导出；项目 JSON 是结果快照，不是完整原始矩阵备份，也尚无一键导入恢复功能。

所有非总览页面的标题右侧都提供“← 返回上一页”和“返回项目总览”。页面内从病害清单进入三维定位时，返回按钮会回到刚才的页面；多场景复核页还提供“返回场景总览”和“返回智能解析”，减少在子页面中迷路。

## 设计来源与对应关系

本次先阅读工作区《计划.docx》和《隧道智能检测与数字孪生平台_开发提示词.txt》，再分析 3 分 01.52 秒的模板演示视频。计划书实际为四项编号内容，因此设置四个一级业务模块，避免把所有功能堆在一个三维页面。

模板视频约 48～60 秒的原图/雷达与结果并列布局，被用于雷达管理和智能处理页；约 72～84 秒的三维、指标与环号查询关系，被用于孪生、病害清单和健康评估；约 96 秒的报告入口，被纳入可打印 HTML 报告中心。视频中的大语言模型知识问答未列入本次四部分计划，不在本版本中声称已实现。

新界面沿用深蓝工程底色，以绿色作为操作与选中状态，以红/橙/黄/绿表达风险；图表、清单与三维共用编号、里程、批次和评估版本。原有三维几何、检测车交互和背景资源融入新版工作台，各模块通过统一任务与病害数据联动。

## 当前采用的影像检测算法

当前影像病害检测采用 `algorithm/defect_detect.py` 中的 **crack-seg U-Net 裂缝分割流程**。算法目录还包含抽帧、三维重建、病害射线定位、网格优化和复核页面导出；这些代码作为独立 Python 流程运行。

| 环节 | 当前代码与输出 |
|---|---|
| 输入准备 | `reconstruct.py` / `keyframes.py` 提取与选择原始影像帧 |
| 裂缝候选检测 | `defect_detect.py` 加载本地权重，输出掩码、候选观测和 `detections.json` |
| 模型实验 | `segmentation_experiment.py` 提供裂缝分割训练、验证与保留集评估流程 |
| 三维定位与复核 | `localize_defects.py` 与 `export_web.py` 生成定位输出和离线复核页面 |

在“智能解析 → 智能处理工作流”的“当前影像检测算法”卡片查看算法范围，点击“查看影像检测与三维复核”进入已有结果。环境、权重准备及完整运行命令见 [algorithm/README.md](algorithm/README.md)。源码和权重须按其来源说明在本地准备。

本次移除旧候选识别下拉框、相应工作流步骤与默认注册项。当前影像算法输出的是**裂缝候选**，不代表已支持界面中全部人工标注类别，也不代表确诊。算法结果尚未自动写入主工作台病害记录；本轮按用户要求暂不开发视频、算法结果与仿真的自动联动。RCAN / RTM 继续作为雷达处理的待接入接口，不能替代上述影像检测。
