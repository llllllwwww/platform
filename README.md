# 隧雷智检 · 隧道智能检测与数字孪生运维平台

本地运行的中文工作台，依据《计划.docx》的四项内容组织为“检测采集、智能解析、孪生评估与运维、仿真推演”，并以项目总览串联业务。平台共用病害编号、检测批次、坐标、评估和处置记录，可演示从检测任务到报告导出的完整流程。

本版本包含实际可执行的 CSV 解析、数值预处理、AHP/熵权计算、参数化三维联动和本地处置记录。内置病害、示意雷达信号、健康评分配置与仿真预测均明确标记为演示；真实识别模型与 GPR 设备控制尚未接入；现场视频可接入外部画面，雷达页可导入 CSV / JSON 或接收 HTTP / WebSocket 网关帧；接入画面或矩阵本身不会产生识别结论；新增人工现场标注可把同一病害的类型、先后顺序和位置同步到作业仿真与第三模块孪生，并可显式开启录像进度联动车辆。原有演示病害与健康评分保持独立。

## 在线访问

**https://llllllwwww.github.io/platform/**

平台通过 GitHub Pages 提供在线入口，浏览器直接打开即可使用，无需安装任何环境。建议使用支持 WebGL 的现代浏览器（Chrome / Edge / Firefox / Safari）。**本次仓库版本包含现场视频与外部雷达接入、现场病害对应复核、视频与仿真并排布局，以及 2026 年 10 月 5 日的紧凑车载雷达面板。** `main` 分支更新后由 GitHub Pages 构建，在线内容以成功部署的版本为准；仓库提交与网页部署状态需分别核查。

## 启动

推荐在本目录双击 **启动平台.cmd**。启动器使用 Python 3 标准库，仅监听本机回环地址，并打开：

```text
http://127.0.0.1:8765/index.html
```

也可在本目录运行：

```powershell
python 启动平台.py
```

端口被占用时运行 `python 启动平台.py --port 8766`；无需自动打开浏览器时添加 `--no-browser`。终端按 `Ctrl+C` 停止服务。

前端无需构建、无需 npm 安装，默认演示不需要付费服务、API 密钥或联网接口；接入网络视频或雷达帧时需有可访问的设备 / 网关地址。也可双击 `index.html` 使用文件模式，但浏览器对 `file://` 的本地存储与页面通信存在差异，推荐以上 HTTP 方式。请保留整个目录，不能只复制一个 HTML 文件；三维场景需要支持 WebGL 的浏览器。

| 4. 仿真推演 | `#simulation` 仿真验证工作台 | 雷达示意样本、检测车作业验证、简化圆环结构响应、运维方案比较四个页签 |

建议按总览的“完整演示流程”或《平台架构与使用流程》的分步说明书操作：检测任务 → 雷达数据 → 数值预处理 → 病害清单 → 隧道影像三维复核 → 三维定位 → 健康评估 → 预警处置 → 检测报告，再进入仿真工作台改变参数比较结果。

“检测任务与设备”页面展开“设备配置与项目示意”后，用零依赖内嵌 SVG 展示六类项目配置：三臂智能检测车、车载探地雷达阵列、影像与照明单元、定位与姿态采集、边缘采集与数据终端、安全与辅助保障。点击卡片可查看它与平台页面、数据链路的对应关系；这些图是配置和交互说明，不代表真实硬件已经接入。
检测页改为同屏工作区：顶部为可展开的设备配置区；**左侧现场视频，右侧对应仿真**，两个画面等高对齐；左侧视频下面展开“病害标注与对应”。桌面滚动标注时右侧仿真保持可见，任务列表、全宽作业参数和日志放在工作区下方。设备、来源说明和标注区域的折叠只改变显示，不重建视频或场景。

工作区顶部提供“冻结视频并标注”“病害标注与对应”“作业参数”三个快捷入口。宽度 ≥1000 px 使用双栏，较窄屏幕改为单列；参数表单随宽度采用四、二或一列。视频默认独立播放；在标注区勾选“录像播放联动仿真车（按相对进度）”后，才按该录像的相对进度驱动车辆。原有设备卡片、第一人称、启停、HUD、背景、图层、全屏和任务设置均保留。

第一人称车载雷达 HUD 改为左下角紧凑卡片，让出中央车辆和机械臂视野。默认显示雷达剖面、里程与提示；点击“作业详情”展开环号、速度、机械臂和断面信息，标题右侧“− / +”可收起或恢复整个面板。折叠只调整显示，不重建画布或改变作业状态。

隧道影像三维复核已整合到根目录 `index.html` 的 `#defects` 智能解析页面中，作为病害候选识别后的证据复核区。它包含 `algorithm/web/multiscene` 下的多场景总览、DVP 手持、铁路短片、铁路长片和 TUM VI 鱼眼五个原始 HTML 页面；切换场景时仍使用各自原来的 `viewer.js`、`scene_data.js` 和资源文件。

使用方法：启动平台后进入“智能解析 → 病害清单与复核”，向下滚动到“隧道影像三维复核”。先用“多场景总览”查看重建统计，再切换 DVP 手持、铁路短片、铁路长片或 TUM VI 鱼眼。场景页中的“规则化表面 / 原始重建”、候选位置、帧滑块、分割掩码和录像回放均保持原有交互；页面背景由 `algorithm/web/multiscene/platform-theme.css` 统一到主工作台的深蓝黑与青绿色主题。红色标记仍表示待人工复核的候选，不代表已确认病害。完成后点击页面标题右侧“返回上一页”或场景页顶部“返回智能解析”，再进入第三模块做工程定位。

## 现场病害对应复核

在“检测任务与设备”“雷达数据管理”和“三维数字孪生”增加同一个“现场病害 · 视频 / 雷达 ↔ 仿真 ↔ 孪生”区域。冻结真实视频帧或已保存雷达快照，人工指定病害类型和位置后，三个视图共享 `E-` 开头的编号、类型、里程、环向角和埋深；原视频时间 / 像素点、雷达道号 / 采样点作为证据保留。没有标注时，现场对应场景保持为空。

1. **视频 → 仿真**：导入左侧录像，暂停在候选病害处，点击顶部“冻结视频并标注”（或展开标注区使用“冻结当前视频帧”），在冻结画面点击位置，选择类型并“保存对应病害”。默认 `里程 = 任务起点 + 时间/时长 × 任务长度`；画面横向映射到可调整环向扇区，表面深度为 0。勾选录像联动后，车随录像进度运行；使用“定位并对齐车”可检查某处病害。
2. **雷达 → 对应复核**：导入文件或保存网关帧，选择这份固定快照，点击“冻结当前雷达快照”，选道号 / 采样点并保存类型。下方切换为“雷达信号 · 同源病害对应复核”，使用同一矩阵、道号、采样点和标记，不生成另一份随机信号。缺标定可使用明确标记的相对位置；有标定时填写测线起点、方向、环位、表面零点，并利用真实道间距、采样间隔和介电常数换算。
3. **仿真 → 孪生 → 原证据**：进入第三模块“三维数字孪生”，选择相同任务、“当前任务现场标注”和相同数据源。三维点、展开图、横断面采用同一坐标；“原视频位置”“原雷达位置”可返回正确文件时间或固定快照。重新打开原录像后才能跳转，不会用另一份视频替代。
4. **修改和备份**：同一编号可人工关联视频与雷达证据，关联时类型和位置必须一致；修改统一记录会同步更新各视图。同源时间 / 道号的先后顺序倒置会拒绝保存。“导出对应 JSON”保留位置、来源与视频帧；“导入对应 JSON”校验项目坐标基准、批次、任务和编号后恢复。原视频和雷达完整矩阵仍需另存。

“场景对应来源”可随时切回“原有演示台账”，原 16 处病害、历史曲线和完整交互继续使用。“对应数据源”默认跟随当前输入，也可查看当前任务全部证据；不同任务和批次严格隔离。第一人称、启动 / 暂停、背景、图层和原有雷达控件保留，新增标注不会重建当前作业场景或退出第一人称。

这些是**人工候选与相对位置对应**，未执行自动识别。相对里程、示意雷达埋深和三维标记大小不能当作实测值；现场标注不自动进入 SHI、预警或演示 HTML 报告。手工修订坐标后旧相对映射失效，使用定位按钮检查新位置；连续录像联动只作用于仍采用相对时间映射的标注。

已下载并实际读取 3 个公开混凝土视频，选取 9 个带真实帧的人工候选观测，验证类型、时间顺序、精确坐标、源隔离、车载联动、孪生回溯和雷达同道 / 同点标记。它们不是本项目隧道实测数据，也没有里程真值；结果不代表识别准确率。来源及文件校验保存在本地 `tests/output/public-videos/sources.json`，对应记录在 `tests/output/现场病害对应验证.json`，具体断言和边界见 [验证记录](验证记录.md)。

可直接试用已经完成的验证：在默认批次 `B202609`、任务 `T-001` 的对应区导入本地 `tests/output/现场病害对应验证.json`，再在现场视频区打开 `tests/output/public-videos/cracks.mp4`。当前源会显示这个视频的 3 条候选标注，勾选录像联动或点击“定位并对齐车”即可对照。首次导入即可，重复编号会拒绝；雷达回溯需原浏览器目录中保留同编号快照；单独重导入矩阵会生成新编号，须重新绑定，不能伪造旧快照。

完整点击步骤见 [平台使用说明](平台使用说明.md) 的“现场病害对应复核”；可视化模块关系与 **19 步**说明书见 [平台架构与使用流程](平台架构与使用流程.html)。

## 现场视频监测与仿真作业

进入“01 检测采集 → 检测任务与设备”，在左侧接入现场视频，与右侧仿真对照：

1. **本地录像回放**：选择浏览器可解码的 MP4 / WebM 等文件，直接播放、暂停和拖动进度；文件只在本机读取，明确显示为录像回放。
2. **网络监测源**：填写设备或视频网关提供的 HTTP(S) 视频直链，选择视频 / MJPEG 格式及源端用途，再点击“连接视频源”。网络源的直播真实性和延迟仍需由源端核实。
3. **摄像头 / 采集卡**：通过本地启动器进入平台，选择默认或指定设备并允许摄像头权限；仅采集视频，不请求麦克风。
4. **截图与追溯**：接收到画面后可截图为 PNG，并下载独立的视频接入记录 JSON，包含任务、批次、来源、截图时间和录像位置。

原生 HLS 仅在浏览器自身支持时播放；RTSP / RTMP 地址需要设备或视频网关先转成浏览器可播放的 HTTP(S) 地址。网络源可能允许观看而禁止跨域截图，界面会提示限制。刷新浏览器不会自动恢复文件选择或视频连接；任务 / 批次改变会断开原来源，切换到其他业务页会暂停录像、断开网络源并释放摄像头，返回后可手动重连。

视频区为独立的观察与取证入口，不会自动识别病害、生成雷达数据或控制真实检测车。主工作台项目 JSON 包含业务台账及现场对应记录，HTML 演示报告仍以原评估台账为范围；原视频与单独截图需另存，对应 JSON 会保留冻结帧。没有新增前端依赖或视频上传服务。

## 雷达外部数据与对应复核 / 原有仿真

进入“01 检测采集 → 雷达数据管理”，上方是“雷达采集 · 外部数据”，下方可在“雷达信号 · 仿真演示”和“雷达信号 · 同源病害对应复核”之间切换。原有 B-scan、单道切换、色标增益、横向缩放、示意异常区域、样例下载和智能处理入口均保留；两区使用独立的显示控件。

1. **外部文件**：选择数值 CSV，并按需导入 / 粘贴 JSON 标定；也可直接导入包含 `matrix` 和 `metadata` 的 JSON 帧文件。点击“解析并导入”后显示来源声明、任务 / 批次、测线、源端采集时间和本机导入时间。样例明确标为非实测，外部文件的真实性不由平台自动确认。
2. **设备 / 网关数据源**：选择 HTTP(S) JSON 帧轮询或 WebSocket 文本 JSON 帧，填写源端地址并连接。HTTP 间隔为 1～30 秒；WebSocket 最多显示每秒 5 帧，超出帧不展示或归档。网关需提供完整矩阵快照，HTTP 跨域读取需源端允许；当前没有内置雷达网关或专有设备驱动。
3. **保存后再处理**：接收帧只预览，点击“保存本帧到数据目录”后形成独立快照，并选为“当前数据”。再点击“进入智能处理”运行实际预处理，后续接收帧不改写已保存快照。
4. **原始数据保存**：可下载当前矩阵 CSV 和含完整矩阵、标定、来源、时间与最近接入事件的 JSON。主工作台项目 JSON / HTML 报告仍不附带原始矩阵；重要数据需另行保存。

重复帧不会刷新采集 / 接收时间；错误帧、批次 / 任务冲突、超限数据和二进制专有流会明确拒绝。离开雷达页停止网络接入，返回需要手动重连；切换任务或批次会释放连接并清除旧预览，避免数据串用。未保存的接入帧刷新后丢失，已保存目录沿用本地浏览器存储。

坐标轴仅使用已提供的标定；缺少道间距或时间标定时显示道号 / 采样点，不补造物理埋深。图像色标和单道波形做显示归一化，原始数值保持不变。JSON 接入格式见 [雷达帧样例](examples/radar_stream_sample.json) 和 [数据接入说明](真实算法与数据接入说明.md)。

## 默认项目与数据边界

- 示范隧道长 **48 m**，里程 **K3+128—K3+176**，40 环、环号 980—1019，环宽 1.2 m，内半径 2.7 m，衬砌厚度 0.35 m。
- 最新批次为 `B202609`，历史批次为 `B202607`；16 条演示病害沿用原平台。历史直径与长度按当前值的 0.8 倍、面积按 0.64 倍派生，并非历史实测。
- 列表、三维与证据通过病害编号联动；复核按批次独立保存。CSV 导入的数据保持独立来源，**不会自动生成或覆盖病害台账**。
- 项目 JSON 导出按当前批次筛选任务、预警、日志、雷达目录与治理任务。全批次评估与当前筛选诊断分分别输出；没有批次归属的外部分析明确标记为项目全局参考。
- 所有业务状态保存在当前浏览器的 `localStorage`，不上传服务器。不同浏览器、端口及文件模式拥有独立存储。浏览器清理数据后记录可能丢失，应及时导出；项目 JSON 是结果快照，不是完整原始矩阵备份，也尚无一键导入恢复功能。

所有非总览页面的标题右侧都提供“← 返回上一页”和“返回项目总览”。页面内从病害清单进入三维定位时，返回按钮会回到刚才的页面；多场景复核页还提供“返回场景总览”和“返回智能解析”，减少在子页面中迷路。

CSV 为纯数值矩阵，无表头，行是采样点、列是道；至少 2×2，至多 512×2048，单文件不超过 5 MB。缺少道间距/时间标定时显示道号/采样点，不编造实际距离、时间或埋深。

## 设计来源与对应关系

本次先阅读工作区《计划.docx》和《隧道智能检测与数字孪生平台_开发提示词.txt》，再分析 3 分 01.52 秒的模板演示视频。计划书实际为四项编号内容，因此设置四个一级业务模块，避免把所有功能堆在一个三维页面。

模板视频约 48～60 秒的原图/雷达与结果并列布局，被用于雷达管理和智能处理页；约 72～84 秒的三维、指标与环号查询关系，被用于孪生、病害清单和健康评估；约 96 秒的报告入口，被纳入可打印 HTML 报告中心。视频中的大语言模型知识问答未列入本次四部分计划，不在本版本中声称已实现。

新界面沿用深蓝工程底色，以绿色作为操作与选中状态，以红/橙/黄/绿表达风险；图表、清单与三维共用编号、里程、批次和评估版本。原有三维几何、检测车交互和背景资源融入新版工作台，各模块通过统一任务与病害数据联动。

## 底层算法

平台的病害识别能力由 `algorithm/` 目录下的深度学习算法提供，与前端解耦：

| 环节 | 实现 |
|---|---|
| **数据** | 17338 张真实隧道衬砌现场照片（裂缝 / 渗漏 / 无病害）+ 带像素掩码的 TTD / CTCD |
| **标注策略** | 主线照片只有文件夹级标签 → 先用带掩码数据训练 AFPN-Seg 分割器，再伪标注生成检测框 |
| **模型** | YOLO11 + **AFPN**（Asymptotic Feature Pyramid Network，官方实现等价移植为纯 PyTorch） |
| **任务** | 检测 / 分割双头，类别：裂缝 crack、渗水 water、渗漏析出物 leaching |

数据全部由脚本一键下载（含来源链接与许可），训练验证全流程可复现：

```powershell
cd algorithm
python scripts\download_data.py                 # 下载数据（约 2.6 GB）
.\scripts\run_pipeline.ps1                      # 训练 + 验证 + 测试全流程
```

详见 [`algorithm/README.md`](algorithm/README.md)（环境、数据来源、切分防泄漏规则、模型接线）
与 [`algorithm/docs/VALIDATION.md`](algorithm/docs/VALIDATION.md)（实验验证边界与结果说明）。

> 前端顶栏标注的解译算法链 **RCAN + RTM + YOLOv7-AFPN**，当前已实现检测段（AFPN 颈部），
> RCAN 与 RTM 为后续阶段。
