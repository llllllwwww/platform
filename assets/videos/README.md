# 隧道检测作业视频示例

本目录随仓库提供三段公开来源的隧道检测作业原视频，以及一份车载雷达视频的浏览器播放副本。原片按来源下载后完整保留；文件总计 118,540,559 字节（约 113.05 MiB），未压缩打包，下载后可直接导入平台。

| 文件 | 内容与用途 | 编码 | 字节数 | 人工待复核时刻 |
|---|---|---|---:|---|
| [metro-tunnel-scan-equipment.mp4](metro-tunnel-scan-equipment.mp4) | 轨道隧道扫描设备近景，原视频 | H.264 | 1,816,867 | 5 / 12 / 20 秒 |
| [metro-tunnel-scan-follow.mp4](metro-tunnel-scan-follow.mp4) | 同一扫描作业的人员跟拍，原视频 | H.264 | 927,054 | 1 / 3 / 5 秒 |
| [highway-tunnel-gpr.mp4](highway-tunnel-gpr.mp4) | 高速公路隧道车载三维探地雷达检测，完整原视频 | HEVC | 68,042,056 | 原片留存，平台推荐下面的兼容副本 |
| [highway-tunnel-gpr-h264.mp4](highway-tunnel-gpr-h264.mp4) | 上述车载雷达原片的浏览器播放副本 | H.264 | 47,754,582 | 10 / 14 / 18 秒 |

两段轨道隧道视频属于同一作业，不代表三个独立工程样本。公开演示片不属于本项目的现场实测数据。车载原片同时包含隧道外道路与后段处理展示，示例只在第一处隧道的 10 / 14 / 18 秒取帧；软件展示画面不是雷达原始矩阵。

## 在平台中使用

1. 下载本目录，或在 GitHub 对应视频文件页使用下载按钮。车载雷达示例选 `highway-tunnel-gpr-h264.mp4`；HEVC 原片是否能直接播放取决于浏览器和系统解码支持。
2. 打开平台 → **01 检测采集 → 检测任务与设备** → **检测车作业场景 · 现场视频**，使用“本地视频”文件控件选择其中一个播放文件。
3. 点击常驻疑似位置复核栏的 **载入本视频示例位置**，等待完成 3 个原帧的提取。平台按完整 SHA-256 匹配文件，从当前视频实际取帧；无需预先导入验收 JSON。
4. 点击疑似点编号，检查左侧原帧标记、右侧仿真点与检测车位置；开启 **到点暂停复核**，播放后按先后顺序停在各点。**录像联动车辆**可同步录像进度。

这 9 条记录是人工选取的待复核位置，类型留空，不是算法检测结论、确诊病害或工程里程真值；多个观察帧也可能对应同一物理位置。

## 来源与文件校验

- 轨道隧道扫描设备及人员跟拍：**昊艾智能官网**，来源页 <https://www.h-eye.cn/Track_inspection/6>。原始文件链接和 SHA-256 见 [sources.json](sources.json)。
- 车载雷达检测：**西南交通大学教师主页**，来源页 <https://faculty.swjtu.edu.cn/zanyuewen/en/yjfx/266774/content/9775.htm>；原视频署名西南交通大学深圳研究院，2025-11。完整 HEVC 原片及 H.264 副本分别保留 SHA-256。

公开页面未注明视频独立复用许可，权利归原发布方。按项目用户要求保留演示素材和出处，不声称取得独立授权；平台代码的许可不覆盖这些视频。

H.264 副本只转换编码为 H.264/yuv420p 并去掉音轨，不改变原视频的分辨率、画幅和视频时序。原片没有被替换或裁剪。

开发复现：`python tests/download_public_videos.py` 优先校验本目录的素材，不重复下载。浏览器专项测试也优先读取本目录，结果写入被忽略的 `tests/output/`；用户录像、算法输入输出及临时截图不会随这批示例上传。
